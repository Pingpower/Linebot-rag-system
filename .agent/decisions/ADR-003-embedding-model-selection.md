# ADR-003: 維持使用 Gemini Embedding 2 作為檢索模型

**狀態**: 已採納
**日期**: 2026-07-17
**決策者**: AI / 用戶

---

## 背景

使用者提議考慮將目前的 Embedding 模型更換為開源且有免費額度的 `jina-embeddings-v5-omni-small`，期望能獲得更好的效果與降低未來成本。

## 決策

「按兵不動」，繼續使用 Google 的 `models/gemini-embedding-2`。

## 考慮的選項

### 選項 A: 遷移至 Jina Embeddings v5 Omni Small

- ✅ 優點：支援多模態（圖片與文字的統一語意空間），有 1000 萬 Token 的免費啟動額度。
- ❌ 缺點：
  1. 輸出為 1024 維度，與目前 Supabase `pgvector` 設定的 768 維度不相容。
  2. 需大幅修改資料庫 Schema 並清除所有歷史向量資料。
  3. 免費額度耗盡後需綁卡付費，且免費 Tier 有嚴格的 Rate Limit (100 RPM)，不利於我們系統大量批次更新知識庫的場景。

### 選項 B: 維持 Gemini Embedding 2

- ✅ 優點：
  1. 768 維度完全相容目前的資料庫架構。
  2. 純文字的語意檢索表現已經是業界頂尖水準。
  3. API 額度與配額在目前的架構下運行穩定。
- ❌ 缺點：無法處理未來可能的多模態檢索需求。

## 理由

系統的穩定性與遷移成本是首要考量。目前剛修復了背景同步失敗的問題，系統的 RAG 檢索功能已經恢復正常運作。除非業務出現強烈的「圖片語意檢索」需求，否則在純文字為主的知識管理場景下，Gemini Embedding 2 已經足夠強大，不值得為了 Jina 承受破壞性資料庫更新的風險與潛在的 Rate Limit 坑。

## 影響

### 正面影響

- 避免了不必要的重構風險，確保系統當下能立刻上線服務。

### 負面影響

- 無。
